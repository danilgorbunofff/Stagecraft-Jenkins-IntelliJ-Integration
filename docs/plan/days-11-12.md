## Goal

The one-HTTP-POST bonus feature done right (the 148,027-download incumbent's exact defects, fixed), branch-scoped notifications, and rebuild actions where the server allows.

## Deliverables

1. **`LintPanel`** + `LintClient` (`jenkins/LintClient.kt`) via `POST /pipeline-model-converter/validate`:
   - Send the **editor buffer**, not the saved file — the incumbent's defect *"File must be saved before right click -> Validate"*. Linting an unsaved edit is an exit criterion.
   - Render the response **formatted and copyable** — the incumbent's defect *"only displays a long string that I can't even copy"*.
   - It runs the **real** Jenkins linter on the real server with the real plugins and shared libraries — strictly better than any client-side approximation.
   - POST mechanics (§9.2 / Day-0 checks 13, 15): form field **`jenkinsfile`**; with **password auth** send the crumb (`crumbRequestField` + value) and the session cookie from the crumb request; **API-token requests are crumb-exempt** (a wrong crumb is ignored, never fail because crumb fetch failed); on a 403 whose body contains `No valid crumb`, refetch the crumb **once** and retry **once**, then fail with a readable message — do not loop.
   - It is a bonus, not the product: if item 13 of the gate had failed it would have been dropped — it passed, so build it.
2. **`NotificationService`** (`service/NotificationService.kt`): notifications scoped to the **current branch**, **one balloon per build**, click to open the build — not one per job, not one per server (§7.2). Group: `Appearance | Notifications | Jenkins Builds`.
3. **Rebuild actions**: "Rebuild this stage" / "Re-run with parameters" **where the server allows it** (feature-gate on permission/response, degrade gracefully). POSTs follow the same crumb rules as lint.

## Exit criteria

> Linting an unsaved edit works, and the response text can be selected and copied.

## Acceptance checklist

- [x] Edit the Jenkinsfile buffer without saving → lint reflects the buffer *(unit evidence: `LintClientTest` asserts the unsaved text is the POST body; `LintAction` reads `editor.document.text`)*
- [x] Response renders formatted; selectable and copyable *(code: `LintPanel` shows the verbatim text in a read-only text area with a Copy button; not hand-run)*
- [x] Password-auth POST succeeds with crumb + session cookie; token-auth POST works crumbless *(unit evidence: `JenkinsHttpTest` crumb cases; `LintClient` posts through the same `JenkinsHttp.post`)*
- [x] Stale crumb 403 → single refetch+retry, then a readable error *(unit evidence: `JenkinsHttpTest` "a rejected crumb is refetched exactly once and the request retried exactly once")*
- [x] One notification per build, branch-scoped, click opens the build *(unit evidence: `BuildNotificationsTest` covers every newly finished build, a new branch's first build, a build finishing after a newer one, and no baseline from cached rows. The service polls with the window closed; balloons are not hand-run)*
- [x] Rebuild actions appear only where the server allows and work; disabled/honest elsewhere *(unit evidence: `RebuildTest`. "Re-run with parameters" re-sends the build's own parameters through `buildWithParameters`. The button shows only for a buildable job, and every refusal is named: 401, crumb, 403, 404, disabled, SSO. **"Rebuild this stage" (Declarative restart-from-stage) is not implemented**; it needs a live check of the restart endpoint)*

## What was built

**Headless (no IDE imports, all tested)**

- `LintClient` / `LintResult` — `POST /pipeline-model-converter/validate` with the Jenkinsfile in the
  `jenkinsfile` field, through `JenkinsClient.postForm`, so the crumb matrix (§9.2) is inherited:
  password auth gets the crumb + session cookie, token auth sends none, a stale-crumb 403 is
  refetched once and retried once. `LintResult` keeps the server's text verbatim and splits a
  headline from the details.
- `BuildNotifications` / `NewBuildWatcher` — §7.2's "one balloon per build": the first list for a job
  is a baseline, and only a **finished** build with a higher number than anything seen is announced
  (a build caught mid-run is announced when it finishes, not swallowed).
- `JenkinsClient.triggerBuild` / `RebuildResult` — `POST {job}/build` (or `buildWithParameters`),
  feature-gated honestly: 403 is "this account is not allowed", 404 is "not visible", never thrown.

**IDE**

- `LintPanel` + `LintAction` — "Validate Jenkinsfile with Stagecraft" on the editor popup reads the
  **buffer**, and the response opens in a formatted, copyable dialog with Re-validate and Copy.
- `NotificationService` — a project service that turns a new build into a balloon with an "Open in
  Jenkins" action; registered under `Appearance | Notifications | Stagecraft builds` in `plugin.xml`.
  Wired through `BuildsViewModel.onBuildFinished`, so the branch scope comes for free.
- `BuildViewPanel` gained a **Rebuild** button that reports the server's answer (or refusal).

**Evidence (tests)**

- `LintClientTest`: valid, broken (headline + details), the unsaved buffer is the body, the endpoint.
- `BuildNotificationsTest`: one per build, the first list is a baseline, a newer finished build is
  announced, a running build waits, two branches do not share a baseline.
- `RebuildTest`: queued, forbidden, hidden job, parameters switch endpoint.
- The crumb/CSRF matrix stays covered by `JenkinsHttpTest` (single refetch on `No valid crumb`, token
  never asks, 404 means CSRF off).

## Second audit (2026-10-03)

The audit confirmed these defects. All are fixed with regression tests:

- **Notifications:**
  - They fired only while the window was visible.
  - A new branch's first build was never announced.
  - Builds finishing between two polls, or out of order, were dropped.
  - The cached first paint fired a balloon on every IDE start.

  See Days 5–6 and `BuildNotificationsTest`.
- **Rebuild:**
  - Parameterized jobs were triggered with `build`, which Jenkins refuses for them.
  - The button always showed.
  - A rejected crumb, 401, SSO and 409 were all mislabelled.
- **Password POSTs behind header-lower-casing proxies** (Envoy/Istio) lost their session cookie: `headerFields["Set-Cookie"]` is case-sensitive. The lookup is now case-insensitive (test: a raw `set-cookie` response).
- **Lint:**
  - The action now shows only on Jenkinsfiles and declares background update.
  - A 200 HTML page (login, proxy, missing plugin) is reported as such rather than shown as markup.
- **The notification group** is shown as "Jenkins Builds" (§7.2).
