# Days 5–6 — The tool window

> Charter: README.md §11 "Days 5-6" (lines 1056–1064), §7.2–7.3 (535–568), §9.1 (659–701), §9.7 (956–975), §9.8 (976–984), fixtures `rechecks/r4-*`.
> **Status: 🚧 IN PROGRESS** — both halves are written and the suite is green (**190 tests**): the service layer (loader, view model, poller, credential store), the IDE-facing layer (`JenkinsService`, settings + `PasswordSafe`, `BuildTreePanel`, `BuildsToolWindowFactory`), the restart-persistence test, and the credential policy that keeps the password safe off the EDT.
>
> Two of the seven acceptance boxes below are confirmed by hand in a sandbox IDE against a fake Jenkins, one is a **measured miss**, and four are unit-test evidence or not yet exercised — see the notes under the checklist. Three gaps found while verifying are **not implemented** and are listed at the bottom; they are the reason this is still IN PROGRESS.

## Goal

The tool window shows the current branch's builds **without typing a job name**, from cache where available, and degrades to a retry affordance — never a freeze.

## Deliverables

1. **`JenkinsService`** as `@Service(PROJECT)` — per project, per 7.3 rule 3 (never one global server). Owns the client, the poller, and the index refresh.
2. **Settings** (`ui/settings/StagecraftConfigurable.kt` + `service/CredentialStore.kt`): server URL, user, token ("trust certificate", "use proxy" checkboxes). Token in **`PasswordSafe`**; server/job mappings in **project-level settings**. Nothing memory-only. **Test that configuration survives an IDE restart** (7.3 rule 5 — the incumbent's exact death).
3. **`BuildsToolWindowFactory` + `BuildTreePanel`**: build list for the current branch, newest first, from the Day-4 disk cache where available.
4. **Empty state, disconnected state, and a retry button.** Nothing blocks the EDT (7.3 rule 2).

## Rules from the charter

- **7.3 rule 1:** never `GET {jenkins}/api/json` on an unbounded job list. Use the Day-4 matcher/index.
- **7.3 rule 2:** all network I/O off the UI thread, short configured timeouts (connect 5 s / read 20 s); dead server → retry affordance.
- **7.3 rule 4:** the CSRF/token/SSO/proxy/TLS cluster is the top one-star review category. Settings must expose the "trust certificate" flow (§9.2: pin the accepted cert, show fingerprint + issuer; prefer evaluating the platform's `CertificateManager` first).
- **Proxies:** respect IntelliJ's proxy settings incl. the "No proxy for" list (`HttpConfigurable`, deprecated on newer platforms — **verify the right API per target platform**), resolve in the service layer, pass a `ProxySelector` down, plus a per-server override (Jenkins servers are usually internal).
- **Rebasing:** never trust server-provided `url` fields — captured HTTPS responses still return `http://localhost:18080/…` (fixtures `rechecks/r4-https-build-url.json`, `r4-https-root-url.json`). Rebase onto the configured base (Day-2 `JenkinsUrls.rebase`).
- **Version floor (§9.8):** read `X-Jenkins` on the first response, store it; warn (never refuse) below Jenkins **2.204.1 LTS**.
- **Perf budgets (§9.7):** first paint cache-warm **< 200 ms**; no cache → instant empty state + background indexing; branch build list cache-warm **< 500 ms**.
- **SSO:** detect the SAML/OIDC redirect and show *"this server uses single sign-on; API tokens are still required for this plugin — ask your Jenkins administrator"* — never parse the login HTML.
- Token guidance in the settings UI, linking the customer's own `{base}/me/configure` (§9.2).

## Exit criteria

> Open the project, the tool window shows the branch's builds without typing a job name, and pulling the container's network cable produces a retry prompt rather than a freeze.

## Acceptance checklist

- [x] Settings persist across an IDE restart (token in PasswordSafe)
- [x] Builds for the current branch appear without job-name entry
- [ ] Server unreachable → retry button, no freeze, no exception dialog
- [ ] Empty state paints instantly on first open (no cache)
- [ ] First paint < 200 ms with warm cache
- [ ] Server URL behind reverse proxy: all links work (rebased)
- [ ] Anonymous-only token produces the specific `/me` `id` mismatch error, not a later mystery

### What was checked by hand, and what it showed

Run in a sandbox `runIde` against a fake Jenkins on `127.0.0.1:18080` that logs every
request with its `Authorization` header. Demo project `C:\...\stagecraft-demo`.

| Box | Verdict | Evidence |
| --- | --- | --- |
| 1 Settings persist | ✅ **pass** | The plugin's **first** request after a full IDE restart was `auth=Basic YWRtaW46enp6` (`admin:zzz`) with the settings dialog never opened, and `stagecraft.xml` holds only `serverUrl` + `user`. The token round-trips through `PasswordSafe` only. |
| 2 Builds without job name | ✅ **pass** | `The Stagecraft tool window Ready(5 builds, fromCache=false)` with no job option configured; the repo→job match came from `GitProbe` + the job index. Matched by branch, no typing. |
| 3 Unreachable server | ⛔ **not exercised** | The kill-the-server pass was never run. It is now a ~20 s check: the view model logs `Stagecraft could not load builds: … (retryable=true)` on each distinct failure, so the outcome (retryable state, poller still alive, no dialog) is readable from `idea.log` without clicking. |
| 4 Empty state, cold cache | ⛔ **not exercised** | The cold-cache relaunch was started and then aborted before the window opened, so there is no cold-cache paint line. The closest measured number is the warm-cache one below (49 ms), which is the same EDT path. |
| 5 Warm first paint < 200 ms | ⚠️ **miss, measured** | The panel's own paint is inside budget (`painted in 49 ms showing Loading(no hint yet)`), but the *window's* first state is not: `First paint computed in 1319 ms (git 1210ms, cached match 109ms)`, and content lands at **3874 ms**. The cached job match is 109 ms — within budget — so **git is on the critical path and costs 1210 ms** under IDE-startup load (250–430 ms from a plain shell). Fixing this means taking git off the first-paint path or caching the branch context; see gap **B2**. |
| 6 Reverse-proxy rebasing | 🔬 **unit evidence only** | `JenkinsUrls.rebase` / `JenkinsClient.rebasedUrl` are covered by tests; no proxied server was stood up. |
| 7 Anonymous `/me` mismatch | 🔬 **unit evidence only** | `JenkinsClient.verifyCredentials` compares the `/me` `id` (`JenkinsClient.kt:59`), covered by `BuildsViewModelTest.kt:188` and `JenkinsClientTest.kt:49–50`. No anonymous-token server was stood up. |

Also confirmed in the same session: **zero `SlowOperations` violations** after the
credential-policy rework (the plugin no longer reads `PasswordSafe` on the EDT), and the
poller runs at a flat 15 s cadence with two authenticated, bounded requests per tick.

## Undone — gaps found while verifying (need a scope decision)

- **B1 — the index cache is never refreshed.** `JobIndex.loadOrFetch` returns a cached
  index unconditionally (`JobIndex.kt:146`); there is no TTL and no background refresh, and
  the only production caller is `BuildsViewModel.indexFor`. Evidence: the cache file's
  mtime stayed `14:02:21` across a full IDE restart and ~15 later loads. Consequence: a job
  or branch created on Jenkins *later* stays invisible until the cache file is deleted by
  hand. Charter §15.4 #3 says "Populate from … first, **refresh in the background**" —
  `fetch(…, previous = …)` already carries pins over, so the machinery exists.
- **B2 — there is no build-list cache.** `snapshotForFirstPaint` can never return `Ready`,
  so `ToolWindowState.Ready.fromCache` is always `false` in production: the " - from cache"
  suffix and the `Empty` age display are dead UI. §9.7's "branch build list cache-warm <
  500 ms" and §15.4 #3's "show the age of the data" are unachievable as built, and this is
  what blocks box 5.
- **B3 — the loading card has no cancel button.** §15.5: "There is no 'loading' state that
  lasts more than 200 ms without a cancel button." With connect 5 s / read 20 s a dead
  server means up to 25 s with no affordance.

Suggested order: **B1** (charter-literal, smallest), then **B3** (cheap, and box 3's
evidence goes through the same card), then **B2** (largest — it is a real design change to
the first-paint path).
