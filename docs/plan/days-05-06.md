## Goal

The tool window shows the current branch's builds **without typing a job name**, from cache where available, and degrades to a retry affordance — never a freeze.

## Deliverables

1. **`JenkinsService`** as `@Service(PROJECT)` — per project, per 7.3 rule 3 (never one global server). Owns the client, the poller, and the index refresh.
2. **Settings** (`ui/settings/StagecraftConfigurable.kt` + `service/CredentialStore.kt`): server URL, user, token ("trust certificate", "use proxy" checkboxes). Token in **`PasswordSafe`**; server/job mappings in **project-level settings**. Nothing memory-only. **Test that configuration survives an IDE restart** (7.3 rule 5 — the incumbent's exact death).
3. **`BuildsToolWindowFactory` + `BuildTreePanel`**: build list for the current branch, newest first, from the Day-4 disk cache where available.
4. **Empty state, disconnected state, and a retry button.** Nothing blocks the EDT (7.3 rule 2).

## Rules from the charter

- **7.3 rule 1:** never `GET {jenkins}/api/json` on an unbounded job list. Use the Day-4 matcher/index.
- **7.3 rule 2:** all network I/O off the UI thread, short configured timeouts (connect 5 s / read 20 s); dead server → retry affordance.
- **7.3 rule 4:** the CSRF/token/SSO/proxy/TLS cluster is the top one-star review category. Settings must expose the "trust certificate" flow (§9.2: pin the accepted cert, show fingerprint + issuer; prefer evaluating the platform's `CertificateManager` first).
- **Proxies:** respect IntelliJ's proxy settings incl. the "No proxy for" list (`HttpConfigurable`, deprecated on newer platforms — **verify the right API per target platform**), resolve in the service layer, pass a `ProxySelector` down, plus a per-server override (Jenkins servers are usually internal).
- **Rebasing:** never trust server-provided `url` fields — what Jenkins returns depends on its root-URL configuration and on what a proxy forwards (the R4 captures show the forwarded `https://localhost:18443/…`; see the corrected R4 row). Build job and build URLs locally; rebase only what cannot be built (`JenkinsUrls.rebase`, context-path aware since the audit).
- **Version floor (§9.8):** read `X-Jenkins` on the first response, store it; warn (never refuse) below Jenkins **2.204.1 LTS**.
- **Perf budgets (§9.7):** first paint cache-warm **< 200 ms**; no cache → instant empty state + background indexing; branch build list cache-warm **< 500 ms**.
- **SSO:** detect the SAML/OIDC redirect and show *"this server uses single sign-on; API tokens are still required for this plugin — ask your Jenkins administrator"* — never parse the login HTML.
- Token guidance in the settings UI, linking the customer's own `{base}/me/configure` (§9.2).

## Gaps found while verifying — all closed

- **B1 — the index cache is never refreshed.** *Fixed 2026-10-03:* the loader refetches a cached index that cannot name the branch (when it is over 60 s old) or that is over 30 min old, and saves the result. Regression tests: `a branch pushed after the index was cached is found by refetching the index`, `a miss on a just-fetched index does not refetch on every poll`, `an old index is refetched even on a hit`.
- **B2 — there is no build-list cache.** *Fixed 2026-10-03:* `BuildListCache` stores each branch's rows (job, builds, `how`, version warning, fetch time) on disk under `{systemPath}/stagecraft/…/builds-{sha1(key)}.json`, and `BranchContextCache` stores the last git remote/branch so the first paint does not wait for git. `snapshotForFirstPaint` now returns `Ready(fromCache=true)`/`Empty` with an age, and the panel shows `- from cache, updated …` and `(checked …)`. Regression tests: `first paint paints the cached rows, with their age, and costs no network`, `an empty build list is cached and painted with its age`, `a cached list for one branch is not painted for another`, plus `BuildListCacheTest`/`BranchContextCacheTest` round-trips and corruption misses. This closes box 5.
- **B3 — the loading card has no cancel button.** *Fixed 2026-10-03:* the loading card carries a **Cancel** button; `BuildsViewModel.cancel()` bumps a generation so the in-flight (blocking) answer is discarded, and the panel stops the poller until the user presses Retry/Refresh. Regression tests: `cancelling a slow load discards its answer`, `retry after a cancel loads again`. This closes box 3.

## Post-audit changes (2026-10-03)

The two ticked boxes were re-verified, and the audit found these defects in the code behind them. All are fixed, each with a regression test:

- **Box 2 was only true on the first run (B1).** A branch pushed after the index was cached was never found, so it showed "svc has no builds yet". That is now fixed through B1 above and the matcher changes in Days 3–4.
- **The poll was not quiet.** Every 15 s tick swapped the build list for the "checking" card and dropped the selection. A refresh over a list on screen now publishes nothing until the answer arrives, and the panel keeps the selection across replacements.
- **The settings dialog defeated `CredentialPlan`.** It pre-filled the stored token, so changing the URL or user re-stored the old token for the new server or user. The field now always starts blank, and the help text says whether a token is stored.
- **Tokens were keyed by server only**, so two projects using one server as two users overwrote each other's token. Keys are now per server and user, and the old per-server entry is migrated on its first read.
- **A new client on every load or poll** meant a new cookie jar, crumb and `/me` call each time, and a new Jenkins session per tick with password auth. `JenkinsService` now reuses one client for as long as the settings it was built from stand, and the loader verifies each client once.
- **Proxy settings** use 2024.2's `JdkProxyProvider` when present and fall back to the deprecated `HttpConfigurable`.

Box 2 stays ticked on the strength of the hand check plus `BuildsViewModelTest` "a branch pushed after the index was cached…". B2 and B3 were closed on 2026-10-03 as described above, taking the suite from 217 to 230 tests; see "Gaps found while verifying — all closed".
