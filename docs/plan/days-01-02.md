## Hard rules

- `dev.stagecraft.jenkins` has **no IntelliJ imports** (§9.1). Proxy/TLS arrive as injected `ProxySelector`/`SSLContext`; `JenkinsHttp` never reads IDE settings.
- **JVM target trap:** emit Java 17 bytecode (`jvmTarget = 17`) while `since-build < 242` (§9.1). *Superseded 2026-10-03: the floor is now 242, set by the Kotlin stdlib (see the audit note below), so the bytecode is Java 21.*
- Cookies: one cookie store per server inside `JenkinsHttp`, reused; never a new client per request (§9.2).
- Crumb: fetched/cached only for password auth; API-token POSTs are crumb-exempt. A wrong crumb is ignored by the server — never fail because crumb fetch failed.
- Timeouts: connect 5 s, read 20 s (§9.2).
- Token validation is `GET /me/api/json` **and** comparing returned `id` to the configured user (a 200 with `anonymous` is not a good token).
- Fixtures: `docs/fixtures/**` is `-text` in `.gitattributes` — byte-exact, never re-normalise line endings.

## Post-audit fixes (2026-10-03)

An audit of the done work found defects in this layer that the 100 tests did not cover. All are fixed, each with a regression test:

- **`JenkinsUrls.rebase` broke every Jenkins under a context path.** It appended the server's whole path to a base that already carried it (`/jenkins/jenkins/…`), and a second rebase added a third copy. It is now idempotent and context-path aware, and `JenkinsClient.builds` builds build URLs locally instead of rebasing them.
- **The JDK passed every 401 to the process-wide `Authenticator`** and replayed the request with its answer, up to 20 times (measured). Inside an IDE that authenticator is the platform's. The transport now refuses server challenges and still passes proxy challenges to the IDE.
- **`/me` id comparison was case-sensitive**, and every mismatch was reported as "anonymous". Ids now compare case-insensitively, as Jenkins does, and an answer from another account gets its own message.
- **`ConsoleDump`** claimed a resent chunk was "not appended" while printing it, and re-polled a running build in a tight loop. The message now matches the behaviour, and polls wait `--interval` ms (default 2000).
- **`gradlew` was committed without its executable bit**, so `./gradlew` failed on macOS, Linux and CI.
- **The `since-build 231` claim was false.** Kotlin 2.4 targets a 2.0+ stdlib, which no IDE before 2024.2 ships. The floor is now 242, `apiVersion` is pinned to 2.0, and kotlinx-serialization is pinned to 1.7.1, the last release built on Kotlin 2.0. The shipped jars were checked class by class against `kotlin-stdlib-2.0.0.jar`.
