## Goal

The stage tree with status and timings (where they honestly exist), failed tests with jump-to-source, and stack-frame hyperlinks that land on the right line of the right file — or no link at all.

## Deliverables

1. **`StagePanel`**: stages with status, **timings only where `wfapi/describe` supplies them**; line counts, **never fake timings**, where it does not (Day-4 fallback). Rendered shape:

   ```
   Build #4811  FAILED   feature/ORD-214   2m 03s
   ├─ PASS  Checkout                  0.4s
   ├─ PASS  Build & Test              1m 21s      [logs] [tests: 412 pass  3 fail]
   ├─ FAIL  Deploy to staging         0m 38s      [logs]   <- pre-selected
   └─ --    Publish                   skipped
   ```

   Clicking a stage swaps the log pane. **The failed stage is open before the user clicks anything** (pre-select). Without `pipeline-stage-view` the failed stage is **inferred** (§9.3) and shown with an "inferred" marker — never presented as fact. Parallel-interleaved stages say *"parallel output, not separable without stage view"* instead of pretending.

2. **`TestResultsPanel`** with per-test jump-to-source. Core Jenkins, no plugin: `GET {build}/testReport/api/json` → `failCount, skipCount, passCount, suites[].cases[]{name, className, status, duration, errorDetails, errorStackTrace}`. Suites carry `enclosingBlockNames` + `nodeId` (fixture `11.testreport.json`: `["Deploy to staging"]`) — **Jenkins already maps tests to stages; use it, no client-side matching.**

3. **Stack-frame hyperlinks, six patterns + three compiler patterns, suffix-matched, no link when the file is absent.**

## Hyperlink patterns (§9.6 — port exactly)

**Stack frames** (class + bare file name, never a path):

1. JVM: `(?:^|\s)at\s+(?:[\w$.\-]*/+)*([\w$.]+)\.([\w$<>\-]+)\(([\w$\-]+\.(?:java|kt|groovy|scala)):(\d+)\)` — the `(?:^|\s)` matters (Jenkins' `errorStackTrace` can start `at` unindented); the `…/+` prefix skips module/loader names (`java.base/`, `app//`).
2. Python: `File "(.+?)", line (\d+)`
3. Go: `^\s+(\S+?\.go):(\d+)` (multiline)
4. Node/JS/TS: `\bat (?:.+? \()?((?:[A-Za-z]:)?[^\s():]+\.(?:[cm]?js|tsx?)):(\d+):\d+\)?`
5. .NET: `\bin (.+?\.cs):line (\d+)`

**Compiler/tool errors** (agent-side paths — the most common way builds actually fail):

6. Maven: `^\[(?:ERROR|WARNING)\] (\S+?\.\w+):\[(\d+),(\d+)\]`
7. Gradle/Kotlin: `^[ew]: (?:file://)?(\S+?\.kts?):(\d+):(\d+)`
8. javac/gcc/go/tsc style: `^(\S+?\.(?:java|c|cc|cpp|h|hpp|go|ts|tsx|js|py|rs)):(\d+)(?::(\d+))?: (?:fatal )?(?:error|warning)\b`

**The two hard rules:**

- **Match by suffix, not absolute path.** The agent's workspace path means nothing locally; longest matching suffix wins, a tie means **no link**.
- **If the file is not in the project, do not offer a link.** A dead hyperlink is worse than plain text; a wrong-file link is a bug report.

**Resolve JVM frames by class, not file name:** `OrderService.java:214` is ambiguous; resolve the fully qualified class (`com.company.order.OrderService`) to a PSI class, then the line. **Prefer the platform's own `ExceptionFilters` / `Filter` via `EditorHyperlinkSupport`** over hand-rolled matching — they already handle inner classes, lambdas, library frames.

## What was built

**Headless (no IDE imports, all tested)**

- `model/TestResult.kt` — `TestCase`/`TestReport`, carrying Jenkins' own `enclosingBlockNames` (the
  test-to-stage mapping) and a summary line.
- `StackFrames` / `StackFrame` — the eight §9.6 patterns (five stack frames, three compiler/tool
  errors), matched textually with offsets. A JVM frame's `pathHint` prepends the class package
  (`com/company/OrderService.java`) so the class, not the bare file name, picks the file.
- `StageView` — the §9.3 fallback chain as data: wfapi first (real statuses/timings, failed stage is
  a fact), console parse second (exact boundaries, inferred failure, a note when parallel output is
  not separable or timings are unavailable).
- `SuffixSourceResolver` — §9.6's resolution rule: longest path-segment suffix wins, a tie is no
  link, an absent file is no link.
- `JenkinsClient.wfapiDescribe` (null on 404 = "no stage view") and `JenkinsClient.testReport`
  (null on 404; converts fractional-second durations to ms once).

**IDE**

- `StagePanel` — the stage list with status/timing (or line counts), the failed stage pre-selected,
  "failed (inferred)" for the console path, and the parallel/timing caveat note. Double-click opens
  the log at the stage's first line.
- `TestResultsPanel` — failed tests first, each opening its own source line.
- `SourceNavigator` — the IDE half of the hyperlink: supplies candidate files by name and opens the
  resolver's winner, or does nothing.
- `BuildViewPanel` — a **Stages / Log / Tests** tab shell; clicking a stage selects the Log tab and
  scrolls. `LogEditorPanel` underlines every frame (`RangeHighlighter`) and navigates on Ctrl/Cmd-click.

**Evidence (tests)**

- `StackFrameTest`: JVM class/file/line + pathHint, the recorded fixture trace (lines 88/214),
  unindented frames, Maven/Gradle/compiler, Python/Node/.NET, plain text.
- `SourceResolverTest`: class-suffix resolution, agent-side path, absent file → null, tie → null,
  longest suffix wins.
- `StageViewTest`: wfapi statuses/timings, empty describe, console inference + notes, parallel note,
  freestyle pseudo-stage.
- `JenkinsClientTest`: wfapi describe present/absent, test report counts/stages/stack trace, missing
  report → null.
