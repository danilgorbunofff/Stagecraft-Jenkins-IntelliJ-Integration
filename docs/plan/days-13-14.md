## Part A — Compatibility matrix (Days 13, first half)

- Run the matrix from §9.2 with Docker, one command per version: **five LTS rows × five columns** (CSRF off, CSRF on, HTTPS, behind proxy, token) = **25 scriptable cells**; password-auth column n/a.

- **Fix whatever breaks. Something will.** Items 1–3 and 13 of the Day-0 gate are the ones that broke under HTTPS; assume the same here.
- Version handling: read `X-Jenkins` once, use only for the floor warning and crumb-behaviour adjustment — never branch the whole client on version.

## Part B — The acceptance test (§7.6)

A stranger, given IntelliJ, a git clone of a multibranch repository, a Jenkins URL + API token, on a **1,000-job server with CSRF on, over HTTPS, behind a proxy**, must:

1. open the project and see the tool window populate **without typing the job name**;
2. see their own branch's builds within **10 seconds**;
3. open the newest failed build, failed stage's log on screen, scrolled to the first error, within **3 seconds**;
4. Ctrl-click a stack frame and land on the right line of the right file;
5. see the build's test results;
6. lose network and see a **retry prompt, not a freeze**;
7. restart the IDE and find the configuration intact.

*If all seven hold, the product is done. That is the whole bar.*

## Part C — Listing and shipping (Day 14)

- **Plugin icon**; screenshots: build tree, failed stage, hyperlink, lint.
- **`plugin.xml` metadata** (since-build per §9.1: low enough to cover 2023.x+, `jvmTarget 17` while `since-build < 242`).
- **Listing text from §8.2, verbatim structure:**
  - Title: **`Stagecraft • Jenkins Build & Log Viewer`** (`Jenkins` = the only keyword that matters; `Build & Log` = what a stuck user types; **NOT** `Pipeline`, `CI/CD`, `DevOps`, `AI`).
  - **Do not lead with "live logs"** — that word is now claimed by partial features. Lead with **your branch** and **jump to source**.
  - First line: *"Your Jenkins build failed. See which stage broke, its log, and click the failing line straight into your editor — without leaving the IDE."*
  - Second line: *"Stagecraft finds your Jenkins server and job from your git remote. It never lists the whole server, so it works on installations with folders, multibranch jobs and thousands of jobs."*
- **Tags:** functional only. **Never `AI` or `Machine Learning`** (§8.4).
- **Product code `PSTAGECRAFT`** — permanent once a paid listing is live; the only public-API proof of a paid listing (Appendix A.6 convention: `P` + uppercase brand).
- **Vendor account + trader-status registration; paid listing; 30-day trial; $29/year.**
- Upload, then **set the review-check reminder for day 7 after publication**.

## Exit criteria

> The plugin is on the Marketplace as a paid listing, and the acceptance test passes on a server that is not the developer's own.

## Out of scope (§11 — do not creep)

No second CI host. No Jenkinsfile completion/colouring. No Jenkins administration. No AI / inference bill / data leaving the customer's network. No free tier. No team licensing. No enterprise SSO beyond a readable error message. **Each is a separate product decision; adding any before a paying customer is how a solo developer ends up with a second unfinished project.**
